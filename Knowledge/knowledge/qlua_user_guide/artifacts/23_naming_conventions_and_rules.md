# Правила разработки и именования переменных (QLua Rules)

Этот документ содержит стандарты кодирования, именования и взаимодействия, принятые в процессе pair-programming между пользователем и Antigravity. Эти правила являются приоритетными при создании любых скриптов в данном проекте.

---

## 1. Системные переменные QUIK (API-поля)
Все переменные, которые считываются из таблиц QUIK или передаются в транзакции, должны строго соответствовать именам, принятым в официальной документации QUIK и рабочих скриптах пользователя:
*   `sec_code` — код инструмента (бумаги/актива).
*   `class_code` — класс инструмента (режим торгов).
*   `firm_id` — идентификатор фирмы (участника торгов).
*   `client_code` — код клиента.
*   `trdaccid` — торговый счет.

Эти системные переменные используются регулярно. Другие системные переменные можно получить из документации QUIK или из дампов колбеков и таблиц при необходимости.

---

## 2. Повторное использование существующего лексикона
При написании новой логики необходимо отдавать приоритет уже существующим и проверенным именам переменных из рабочих роботов пользователя:

### Временные отступы и периоды:
*   `trade_hour` — час торговли.
*   `trd_min_befor` — минуты до начала (строго без буквы 'e' на конце).
*   `period_length` — длина периода в секундах.
*   `reset_before` — время сброса до окончания периода.
*   `all_end_period` / `first_period_end` — расчетные временные метки.

### Флаги состояний робота (strict camelCase):
*   `opn` — состояние открытой позиции (сокращенно от *open*).
*   `stopRpcd` — признак перевыставленного стопа (*stop replaced*).
*   `pendOpen` — признак ожидания открытия позиции (*pending open*).
*   `pendStop` — признак ожидания выставления стоп-заявки (*pending stop*).
*   `pendKillOrder` — признак ожидания снятия активной заявки.

### Расчетные цены:
*   `startPrice` — цена входа в сделку.
*   `initPrice` — стартовая/текущая цена для расчетов.
*   `currentPrice` — последняя цена сделки на рынке.
*   `max_price` / `min_price` — экстремумы цены.
*   `price_limit` — лимит цены.

---

## 3. Правило "Нового имени"
Если для реализации нового алгоритма требуется ввести переменную, которой еще нет в лексиконе:
1.  Имя придумывается в стиле пользователя (кратко, в camelCase для флагов или snake_case для настроек).
2.  При объяснении кода ИИ обязан **явно выделить новое имя жирным шрифтом** с пояснением его назначения, чтобы пользователь мог подтвердить его добавление в лексикон.

## 4. Технические правила проекта
*   **Кодировка:** Все создаваемые и изменяемые `.lua` файлы должны сохраняться исключительно в кодировке **Windows-1251 (CP1251)**.
*   **Автономность тестовых скриптов:** Скрипты в папке `Рабочие функции и части` должны создаваться как полноценные, запускаемые в QUIK файлы (со своими `main`, коллбэками и циклом опроса).
*   **Фильтрация заявок:** Для отсечения чужих ордеров в коллбэках `OnOrder` / `OnTrade` использовать исключительно связку через **`or`** (например, `if order.sec_code ~= sec_code or order.class_code ~= class_code then return end`).
*   **Формат комментариев и сжатость:** Комментарии к переменным и функциям писать строго на той же строке, где они находятся. Код писать максимально вертикально сжатым (компактным), чтобы видеть как можно больше строк кода на одном экране терминала.
*   **Стиль общения и честность:** Обращаться к пользователю строго на **ТЫ**. При любых неясностях ИИ обязан не фантазировать, а честно писать **"Я не поняла"** и переспрашивать напрямую.
*   **Запрос планов ("что осталось сделать"):** По любому запросу пользователя, похожему по смыслу на "что осталось сделать" или "какой план", ИИ обязан выводить четкий структурированный пошаговый план действий (чек-лист) с точным подсчетом общего количества действий (например, "9 действий в 3 шага"), разбитый по логическим блокам.
