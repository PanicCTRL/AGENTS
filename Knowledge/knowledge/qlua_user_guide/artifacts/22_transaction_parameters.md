# Формат параметров транзакций (для sendTransaction)

Функция `sendTransaction(transaction)` в QLua принимает таблицу Lua, ключами которой выступают **строковые параметры** на английском языке (из фиксированного формата импорта транзакций). 

Ниже описаны все основные параметры и принимаемые ими значения, необходимые для сборки заявок.

---

## Обязательные параметры (для большинства транзакций)

| Параметр | Значение / Описание |
|----------|----------|
| `TRANS_ID` | Уникальный номер транзакции (задается программистом от 1 до 2 147 483 647). Обязателен всегда. |
| `ACTION` | Вид транзакции (команда). Основные значения:<br>— `NEW_ORDER` (новая лимитная/рыночная заявка)<br>— `NEW_STOP_ORDER` (новая стоп-заявка)<br>— `KILL_ORDER` (снять заявку)<br>— `KILL_STOP_ORDER` (снять стоп-заявку)<br>— `KILL_ALL_ORDERS` / `KILL_ALL_FUTURES_ORDERS` (снять все заявки) |
| `CLASSCODE`| Код класса (например, `TQBR`, `SPBFUT`). |
| `SECCODE` | Код инструмента (например, `SBER`, `SRM3`). |
| `ACCOUNT` | Торговый счет Трейдера (например, `L01-00000F00` или `SPBFUT00009`). Чувствителен к регистру! |

---

## Параметры для обычных заявок (NEW_ORDER)

| Параметр | Значение / Описание |
|----------|----------|
| `OPERATION`| Направление заявки. `B` — купить (Buy), `S` — продать (Sell). Обязательный параметр. |
| `QUANTITY` | Количество лотов в заявке. Обязательный параметр. |
| `PRICE` | Цена заявки. Обязательный параметр. Для рыночной акции ставится `0`. Для рыночного фьючерса нужно указывать наихудшую цену (максимальную для покупки, минимальную для продажи). |
| `TYPE` | Тип заявки. `L` — лимитированная (по умолчанию), `M` — рыночная. |
| `CLIENT_CODE`| Код клиента. Можно добавлять текстовый комментарий через разделитель. |
| `FIRM_ID` | Код фирмы (идентификатор участника торгов). |
| `EXECUTION_CONDITION`| Условие исполнения. `PUT_IN_QUEUE` (в очередь - по умолч.), `FILL_OR_KILL` (FOK - немедленно или отклонить), `KILL_BALANCE` (IOC - снять остаток). |

---

## Параметры для стоп-заявок (NEW_STOP_ORDER)

| Параметр | Значение / Описание |
|----------|----------|
| `STOPPRICE`| Стоп-цена, при достижении которой активируется заявка. |
| `STOP_ORDER_KIND`| Тип стоп-заявки:<br>— `SIMPLE_STOP_ORDER` (стоп-лимит, по умолчанию)<br>— `TAKE_PROFIT_STOP_ORDER` (тейк-профит)<br>— `TAKE_PROFIT_AND_STOP_LIMIT_ORDER` (тейк-профит и стоп-лимит)<br>— `WITH_LINKED_LIMIT_ORDER` (со связанной заявкой). |
| `EXPIRY_DATE`| Срок действия. `GTC` (до отмены), `TODAY` (до конца сессии), дата `ГГГГММДД`. |
| `OFFSET` | Отступ от максимума/минимума (для Тейк-профита). |
| `OFFSET_UNITS`| Единицы отступа: `PERCENTS` (проценты, шаг 0.01%), `PRICE_UNITS` (в шагах цены). |
| `SPREAD` | Защитный спред (для Тейк-профита). |
| `SPREAD_UNITS`| Единицы спреда: `PERCENTS` или `PRICE_UNITS`. |
| `STOPPRICE2`| Цена условия «стоп-лимит» (для комбинированных заявок). |
| `MARKET_STOP_LIMIT`| `YES`/`NO`. Исполнение по рынку при наступлении стоп-лимита. |
| `MARKET_TAKE_PROFIT`| `YES`/`NO`. Исполнение по рынку при наступлении тейк-профита. |
| `IS_ACTIVE_IN_TIME`| `YES`/`NO`. Заявка действует в интервале времени. |
| `ACTIVE_FROM_TIME`| Время начала действия (`ЧЧММСС`). |
| `ACTIVE_TO_TIME`| Время окончания действия (`ЧЧММСС`). |

---

## Параметры для снятия заявок (KILL_ORDER / KILL_STOP_ORDER)

| Параметр | Значение / Описание |
|----------|----------|
| `ORDER_KEY` | Номер обычной заявки, которую нужно снять (при `ACTION = KILL_ORDER`). |
| `STOP_ORDER_KEY`| Номер стоп-заявки, которую нужно снять (при `ACTION = KILL_STOP_ORDER`). |
| `BASE_CONTRACT` | Код базового актива. Обязателен при массовом снятии заявок на ФОРТС (`KILL_ALL_FUTURES_ORDERS`). |

---

> **Важно для LUA:**
> Все ключи и строковые значения в таблице, передаваемой в `sendTransaction`, должны быть строками (например, `tostring(price)`). Значения параметров (B, S, L, M, NEW_ORDER) чувствительны к регистру.

---

## Статусы выполнения транзакции (OnTransReply)

Когда вы отправляете транзакцию из скрипта, сервер отвечает через функцию обратного вызова `OnTransReply(trans_reply)`. Поле `trans_reply.status` будет содержать один из следующих кодов (они же пишутся в .tro файл):

| Статус | Описание |
|--------|----------|
| `0` | Транзакция отправлена серверу. |
| `1` | Транзакция получена сервером QUIK. |
| `2` | Ошибка при передаче в торговую систему (например, нет подключения шлюза биржи). |
| `3` | **Транзакция выполнена.** (Заявка успешно зарегистрирована на бирже). |
| `4` | **Транзакция отклонена торговой системой биржи.** Текст ошибки будет в поле `trans_reply.result_msg`. |
| `5` | Транзакция не прошла проверку сервера QUIK (нет прав). |
| `6` | **Транзакция не прошла проверку лимитов QUIK.** (Не хватает денег или ГО). |
| `10` | Транзакция не поддерживается торговой системой. |
| `11` | Ошибка подписи (неправильные ключи). |
| `12` | Таймаут ожидания ответа. |
| `13` | Транзакция отвергнута (попытка кросс-сделки с самим собой). |

> В случае ошибки (статусы 4, 5, 6) обязательно читайте текстовое описание ошибки — оно подскажет, почему заявка была отвергнута.
